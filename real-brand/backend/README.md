## 운영 앱 분리
- 기존 `main`의 뉴로터치 챌린지 앱과 기존 Supabase 프로젝트의 데이터·테이블·API 키는 건드리지 않는다.
- 공식 홈페이지는 별도 Vercel 프로젝트, 직원 로그인 데이터는 **새 Supabase 프로젝트**로 분리한다.
- `001_staff_access_DRAFT.sql`은 검토용 초안. 실제 적용 전 마이그레이션 테스트 필요.

## 권한 구분
- 대표 admin: 전체 강사 계정 및 업무 데이터를 조회. 탈퇴 처리는 제한된 서버 전용 작업을 통해 진행.
- 강사 instructor(active): 본인 프로필·출강 기록·초안 작성·수정. 다른 강사 데이터 조회 금지.
- 강사 paused/inactive: 기존 본인 기록 조회 정책과 별개로 작성/수정 차단. 실제 제품에서는 비활성화 시 로그인 세션 및 비공개 공유 링크 무효화 구현 필요.
- 외부 방문자(anon): 내부 테이블 접근 불가. 공개 교육 프로그램은 별도 검수된 publish 테이블/웹사이트로 분리.
- RLS 정책만으로 도장/신분증을 저장하지 않는다. 별도의 비공개 버킷, 감사 로깅, 사용자 재인증, 보유기간/삭제 정책이 필수.

## 계정 등록 절차
1. Supabase Auth 인증 수단과 관리자 MFA 결정.
2. 첫 관리자 계정은 신원을 확인한 운영자가 Supabase 서버 권한으로 수동 지정(클라이언트에서 role 입력 금지).
3. 강사 초대 수락 후 고유코드 발급: 중복 금지·탈퇴 후 재사용 금지.
4. 서버 작업/API에서만 `staff_accounts` INSERT/UPDATE를 실행하고 감사기록 남김.
5. 공개 강사진 프로필과 내부 민감정보 저장소는 별도 테이블/공개 범위로 분리.

## 출시 전 필수 검증 테스트
- 미인증 사용자가 내부 테이블 SELECT/INSERT 못 함.
- A강사로 로그인 시 B강사 문서/프로필/출강 records SELECT·UPDATE 실패.
- A강사가 요청에서 owner_id를 B로 바꿔 INSERT 실패.
- A강사가 role/status를 admin으로 변경 불가.
- paused/inactive 강사는 새 문서/출강 이력 INSERT 실패.
- admin은 전체 직원의 비민감 업무 기록을 조회 가능.
- 강사 공개 승인 및 권한 해제는 서버 측 승인된 워크플로에서만 처리.
- 탈퇴한 강사의 과거 합법적인 업무 기록은 남되 신분증/직인 파일은 보유 근거에 따라 만료·삭제.
- 인증 없이 쿼리 URL을 직접 입력해도 관리자/강사 화면 데이터 유출 없음.
- 부하·모바일 및 에러 시 데이터 유출 없는 메시지 표시.
- 교육계획서/견적서 필드 변경 이력과 PDF 버전 불변성 확인.
